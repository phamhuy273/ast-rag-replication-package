\begin{abstract}
This compendium provides the complete, unabridged set of 10 empirical benchmark tables produced during the comparative evaluation of Abstract Syntax Tree (AST) chunking versus sliding-window line chunking in Retrieval-Augmented Generation (RAG) for source code. Every table is paired with concise empirical takeaways, methodological commentary, and statistical decisions specifically prepared for in-depth empirical evaluation and scientific reporting. All figures and tables are generated strictly via automated scripts governed by zero-hardcoding standards.
\end{abstract}

\noindent\textbf{Empirical Findings \& Methodological Takeaways (Table II):}
\begin{itemize}[nosep,topsep=2pt,partopsep=0pt,itemsep=2pt]
    \item \textbf{Syntactic Integrity:} Pure AST chunking delivers near-flawless syntactic parseability (97.9\% clean parse by tree-sitter) and 100.0\% intact boundaries. In contrast, fixed 50-line chunking slices across syntax boundaries in 56.0\% of chunks (only 22.4\% clean parse, 44.0\% intact boundary).

    \item \textbf{The Necessity of Fallback:} Real-world code contains long functions exceeding embedding context limits (512 tokens). Line chunking produces 28.6\% truncated chunks. AST resolves this via sliding-window fallback, yielding an overall 35.7\% fallback rate (13.1\% in Java, 52.1\% in React/TS).
\end{itemize}

\input{tables/table_T4.tex}
\FloatBarrier
\vspace{-0.1cm}
{\small
\noindent\textbf{Empirical Findings \& Methodological Takeaways (Table IV):}
\begin{itemize}[nosep,topsep=2pt,partopsep=0pt,itemsep=2pt]
    \item \textbf{Comp 1 (Pre-registered Primary Hypothesis):} AST+Header vs. Line No-Header shows $\Delta = -0.0138$ (95\% CI $[-0.088, 0.058]$, $p_{\mathrm{raw}} = 0.8532$, $p_{\mathrm{Holm}} = 0.8532$, $W = 155.0$). \textbf{The pre-registered hypothesis that AST chunking outperforms line chunking is not supported.}
    \item \textbf{Comp 2 (Pure Chunking):} In the absence of context headers, AST chunking is statistically inferior to line chunking ($\Delta = -0.1258$, $p_{\mathrm{Holm}} < 0.001$, $W = 22.0$). Line chunking won in 20 out of 25 JDs.
    \item \textbf{Comp 3 (Header on AST):} Adding structural context headers to AST chunks produces a large, highly significant performance boost ($\Delta = +0.1120$, $p_{\mathrm{Holm}} = 0.0031$, $W = 46.0$, 19 wins vs. 6 losses). Context headers are the true driver of AST retrieval capability.
    \item \textbf{Comp 4 (Header on Line):} Adding headers to line chunks produces a modest, non-significant gain ($\Delta = +0.0291$, $p_{\mathrm{Holm}} = 0.7332$, $W = 128.0$).
    \item \textbf{Comp 5 (Exploratory Contrast):} Comparing the two header-equipped systems reveals Line With-Header leads AST With-Header by $+0.0428$ ($p_{\mathrm{raw}} = 0.1355$, 95\% CI $[-0.106, 0.021]$, $W = 97.0$).
\end{itemize}
}

\input{tables/table_T5.tex}

{\small
\noindent\textbf{Empirical Findings \& Methodological Takeaways (Table V):}
\begin{itemize}[nosep,topsep=2pt,partopsep=0pt,itemsep=2pt]
    \item \textbf{Java Stratum ($N=15$):} AST+Header closely tracks Line+Header (0.515 vs. 0.536, $\Delta = -0.021$). In object-oriented languages with disciplined class/method structures, AST chunking remains highly competitive.
    \item \textbf{React/TypeScript Stratum ($N=10$):} AST+Header lags Line+Header significantly (0.369 vs. 0.445, $\Delta = -0.075$). The high syntactic complexity of JSX, functional components, hooks, and large files forces high fallback rates (52.1\%), diminishing AST advantages.
    \item \textbf{Methodological Conclusion:} Language characteristics govern chunking utility. AST is viable in structured OOP (Java) but suboptimal in modern multi-paradigm web stacks (React/TS).
\end{itemize}
}

{\small
\noindent\textbf{Empirical Findings \& Methodological Takeaways (Table VI):}
\begin{itemize}[nosep,topsep=2pt,partopsep=0pt,itemsep=2pt]
    \item \textbf{Severe Fallback Domination Without Headers:} For AST No-Header, 70.0\% (175/250) of all retrieved top-10 items across all queries were actually line-fallback chunks! This reveals that without headers, the AST pipeline relies almost entirely on fixed sliding windows to retrieve relevant code.
    \item \textbf{Header Restores Pure AST Retrieval:} Adding structural context headers elevates pure AST retrieval to 54.0\% (135/250) at the re-ranking tier and 66.4\% (166/250) at the dense tier.
    \item \textbf{Scientific Insight:} Unaugmented AST functions poorly because pure method snippets lack enclosing class and namespace metadata; neural encoders favor longer, broader fallback windows unless explicit context headers are prepended.
\end{itemize}
